# raccoonix T2 user manual

Generated from `catalog/tools.toml`. Regenerate with `PYTHONPATH=python/src python3 -m t2offsec manual` and do not edit this file by hand.

raccoonix T2 is the Fedora package of the t2refit offensive lab for Intel Macs with an Apple T2 chip. The git repository is t2refit. The RPM name is `raccoonix-t2`. The commands are `t2offsec` and `t2offsec-inventory`.

raccoonix-t2 is an independent project. It is not the Fedora Project, Apple, Kali or Offensive Security, or the upstream author of a catalogued tool. Those names identify the other projects.

Use this manual in an authorized lab: machines, networks, and files you are allowed to test. An entry tells you what a tool is, which Fedora package carries it, the command that prints that tool's own help, the upstream documentation, and the license. The help command is the whole usage note. Module lists, payloads, and attack steps stay in the upstream project.

Fedora package names were read from the Fedora 44 mdapi on 2026-10-16. Re-check a name in dnf before you rely on it months later.

## Install from a local RPM

`raccoonix-t2` 0.1.0 installs the catalog, this manual, `t2offsec`, and `t2offsec-inventory`. Lab tools such as Nmap stay in their own Fedora, COPR, or upstream packages. Wordlists, firmware, and proprietary blobs stay out of the `raccoonix-t2` RPM.

No public dnf repository carries this package, and no GitHub release has been published. Build the RPM on Fedora from a tarball of the t2refit repository.

A GitHub archive of tag `v0.1.0` is named `t2refit-0.1.0.tar.gz` and unpacks as `t2refit-0.1.0`. The leading `v` is only on the tag. Until that tag exists, make the same archive from a checkout:

```bash
mkdir -p "$HOME/rpmbuild/SOURCES"
git archive --format=tar.gz --prefix=t2refit-0.1.0/ \
  -o "$HOME/rpmbuild/SOURCES/t2refit-0.1.0.tar.gz" HEAD
rpmbuild -ba packaging/raccoonix-t2.spec
```

rpmbuild writes an arch RPM under `~/rpmbuild/RPMS`. Install that file:

```bash
sudo rpm -Uvh "$HOME"/rpmbuild/RPMS/*/raccoonix-t2-0.1.0-*.rpm
```

After that install:

| Path | What it is |
| --- | --- |
| `/usr/bin/t2offsec` | Read-only catalog command |
| `/usr/bin/t2offsec-inventory` | Read-only version inventory |
| `/usr/share/raccoonix-t2/catalog/tools.toml` | Tool catalog |
| `/usr/share/doc/raccoonix-t2/manual.md` | This manual |
| `/usr/share/licenses/raccoonix-t2/NOTICE` | Apache-2.0 and third-party notices |

Confirm the checkers without running a lab tool:

```bash
t2offsec groups
t2offsec check --tool nmap
t2offsec-inventory --tool nmap
```

`present` means the tool is installed. `absent` means it is not. Either result is a successful check.

From a checkout, before the RPM exists, run this from the repository root:

```bash
PYTHONPATH=python/src python3 -m t2offsec groups
```

The checker reads `--catalog`, then `T2OFFSEC_CATALOG`, then `/usr/share/raccoonix-t2/catalog/tools.toml`, then `catalog/tools.toml` in the current directory. It does not search parent directories.

## Update

Build a newer RPM with the same `git archive` and `rpmbuild` steps, then install it again with `rpm -Uvh`. That replaces the files from the previous `raccoonix-t2` package.

## Uninstall

```bash
sudo dnf remove raccoonix-t2
```

When the package was installed with `rpm -Uvh` and dnf has no record of a repository copy, remove it by name:

```bash
sudo rpm -e raccoonix-t2
```

Removing `raccoonix-t2` leaves Nmap and the other lab tools installed. Those are separate packages.

## Troubleshooting

- `catalog/tools.toml not found`. The shell is not at the repository root, and the RPM is not installed. Pass `--catalog PATH` or set `T2OFFSEC_CATALOG` to the catalog file.
- `cannot read catalog` or `not valid TOML`. The command exits 2 and prints one line. Point it at a readable `catalog/tools.toml`.
- `rpmbuild` cannot find `t2refit-0.1.0.tar.gz`. Put that file in `~/rpmbuild/SOURCES`. The directory inside the tar is `t2refit-0.1.0/`.
- A command is missing after install. Open a new shell. The binaries are `/usr/bin/t2offsec` and `/usr/bin/t2offsec-inventory`.
- `rpmbuild` stops on a missing compiler or Python. Fedora needs `python3-devel`, `cargo`, `rust`, `gcc`, and `rpm-build` to build this spec.

To add a group of lab tools after the package itself is installed, use [install.md](install.md). `t2offsec packages --group recon` prints the official Fedora names for that group's own tools.

## How to read an entry

1. Read the one-line description.
2. Install the Fedora package when the entry names an official package. COPR and upstream entries say which path is the closest one.
3. Run the help command. It asks that program to print its own usage.
4. Use the upstream link for the project's own documentation.
